任务 T12.1 · /actions 通道 + HMAC 一次性令牌 + HITL 审批

id：T12.1 ｜ 所属模块：M12 ｜ 优先级：P0

一句话目标：从 0 建修复通道与人在环审批：挂起可恢复、批准即签发一次性令牌、执行前 dry-run。

前置知识（≤2 新概念）

  • HITL interrupt/审批：图执行到 approval 节点时 interrupt() 挂起，等人工 resume（批准/驳回）。Java 类比：审批流走到审批节点挂起，等人点"同意"才继续，状态靠 checkpointer 持久化。📖 https://docs.langchain.com/oss/python/langchain/human-in-the-loop （interrupt，需核实锚点）· video-2 P71-74「人工介入·审批·中断」
  • HMAC 一次性令牌：批准时签发一个含 exp/nonce 的签名令牌，网关验签 + nonce 一次性消费。Java 类比：一次性支付令牌——签名防伪、过期作废、用过即失效。📖 https://itsdangerous.palletsprojects.com/ （签名+过期）+ https://docs.python.org/3/library/hmac.html （compare_digest）

🟢 第 1 段 · 复刻

  • 读什么：itsdangerous URLSafeTimedSerializer（签名+过期）官方样例；LangGraph interrupt() 官方最小样例。
  • 跑什么：各跑一次——签发/验一个带过期的令牌；跑一个 interrupt 挂起→resume 的迷你图。

🟡 第 2 段 · 改造

  • 网关 ActionController POST /api/v1/actions/execute（action 枚举 restart_container/kill_slow_query/revert_config/disable_chaos_flag；target 白名单从 prunus-mume 实际服务名 + redis 推导 [R10]；dryRun=true 只需服务 token 返回预演，dryRun=false 需 approval 令牌）；approval.py 用 interrupt() 挂起，进 interrupt 前先调 dry-run 拿预演；审批 API GET /incidents/{id}/pending、POST /incidents/{id}/decision + CLI copilot approve/reject。

🔴 第 3 段 · 自研

  • 从空文件写 token.py（itsdangerous 签名 + 自研 nonce 一次性持久层）与网关 ApprovalTokenVerifier（验签 + exp + nonce 未消费 + 常量时间比较，任一失败 403）；revert_config 的 Nacos dataId/group 从 prunus-mume 实际约定映射（M1 已勘察）。

落笔顺序

  1. 1
    复刻：itsdangerous 签发/验令牌 + interrupt 挂起-resume 各跑通。
  2. 2
    改造出 /actions/execute + approval interrupt + 审批 API/CLI。
  3. 3
    发一次请求：无令牌 execute → 应 403。
  4. 4
    自研 nonce 一次性 + 白名单 + dry-run。
  5. 5
    验证同令牌第二次提交 → 403（重放）。

关键提示（≤3）

  • 修复与查询通道物理隔离：/actions 独立预算不计、独立审计表。
  • nonce 一次性靠 DB 唯一约束"插入即消费"，防并发重放。
  • dry-run 仍需服务 token，只豁免 approval 令牌。

卡住降级路径（30 分钟没思路）

  • resume 不生效：确认 checkpointer 持久化、thread_id 对（复用 M4）。
  • 视频：video-2 P72-73「用户审批工具的执行·人工填写审批理由」最贴近。
  • 问 AI：「LangGraph interrupt 挂起后，我 kill uvicorn 重启，用 CLI 发 resume 还能继续吗？我的 checkpointer 和 Command(resume=...) 这样写（贴出），对不对？」

任务 T12.2 · remediate 复查 + 评估兜底（judge + runner + smoke 门禁）

id：T12.2 ｜ 所属模块：M12 ｜ 优先级：P1（工程化收尾）

一句话目标：执行修复后复查恢复，并用纯函数判分 + smoke 门禁量化效果。

前置知识（≤2 新概念）

  • 修复复查（动作→指标映射）：带令牌执行动作后等 60s，按动作查对应指标确认恢复（如 revert_config→error_rate 回基线）。Java 类比：发布后跑一次健康检查确认恢复，没恢复就升级不谎报。📖（复用 M2 query_metrics）
  • 纯函数三级判分：结构化字段与真值直接比对（service/class/anchor），零波动、无 LLM judge。Java 类比：断言式比对，输入相同结果永远相同。📖（自研）

🟢 第 1 段 · 复刻

  • 读什么：M2 的 query_metrics（复查靠它，无需新端点）。
  • 跑什么：手动执行一次 revert_config 后，curl query_metrics 看 error_rate 是否回落。

🟡 第 2 段 · 改造

  • 写 remediate.py：带 approval 令牌 execute（dry_run=false）→ 等 60s → 按动作→指标映射复查 stats.last vs 基线（恢复到 2 倍内）→ 未恢复标 escalate 不自动重试。
  • 写 scorer.py：score(truth, report) -> CaseScore(svc_hit,cls_hit,anchor_hit,negative_ok)；aggregate（acc@service/acc@class/全对率/阴性命中率）。

🔴 第 3 段 · 自研

  • 从空文件写 runner.py（注入→等告警→诊断→revert→判分，JSONL；评估模式自动驳回，只测诊断）与 Makefile 的 make smoke（5 例 <15min，acc@service 不回退门禁）。

落笔顺序

  1. 1
    复刻：手动 revert 后 query_metrics 看恢复。
  2. 2
    改造 remediate 复查 + scorer 判分。

  4. 4
