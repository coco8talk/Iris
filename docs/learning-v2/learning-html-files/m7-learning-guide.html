模块 7 · 排查简版（单 Agent 直连工具）+ 证据台账 — 版本 C

greenfield。🟢复刻 create_agent 官方样例 → 🟡改造成持全部工具的排查 Agent → 🔴自研证据台账。本实现永久保留为消融 A2（去 subagent 对照组）。

学完本模块你能做到的 3 件事

  1. 用一个持有全部只读工具的单 Agent（ReAct 循环）把一次告警查到有结论。
  2. 让 Agent 每次取证都把关键结果按格式登记为带编号的证据（EV-M-001…），落盘可回放。
  3. 让结论必须引用 [EV-*]，为 M9 的反幻觉验收打地基。

本模块交付物清单（文件路径级）

  • src/.../agents/evidence.py（EvidenceStore）
  • src/.../agents/simple_investigator.py（单 Agent 排查）
  • src/.../graph/nodes/investigate.py（investigate 节点，接单 Agent）
  • runs/incidents/{id}/evidence/（运行时证据产物）

任务 T7.1 · 证据台账 EvidenceStore

id：T7.1 ｜ 所属模块：M7 ｜ 优先级：P0

一句话目标：从 0 写一个能按类型编号、落盘、防路径穿越的证据台账。

前置知识（≤2 新概念）

  • 证据台账（可回放取证）：每次工具取证把"来源 + 摘要 + 关键摘录"写成一份带编号的证据文件，结论靠引用它们支撑。Java 类比：像结构化的审计日志 + 附件，每条有唯一 id 可溯源。📖（自研；格式见执行计划 §0.6）
  • 防路径穿越：证据只能写进 runs/incidents/{id}/ 子目录，拒 ../绝对路径/软链逃逸。Java 类比：文件上传时校验落地路径必须在白名单目录内，防目录穿越漏洞。📖 https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html （路径穿越防护，需核实锚点）

🟢 第 1 段 · 复刻

  • 读什么：Python 标准 pathlib 写文件 + 一个带 frontmatter 的 Markdown 样例结构。
  • 跑什么：手写个最小函数把一份 {frontmatter}\n正文 写进指定目录，先证明落盘 OK。

🟡 第 2 段 · 改造

  • 写 EvidenceStore(incident_id)：new_id(kind: "M"|"L"|"T"|"S") -> "EV-M-001"（按类型递增）、write(evidence_id, source, agent_role, degraded, summary, excerpt) -> Path（§0.6 格式）、list_ids/read、write_alert(alerts)。

🔴 第 3 段 · 自研

  • 从空文件写防穿越校验：所有写路径 resolve() 后必须是 runs/incidents/{id}/ 的真实子目录，否则抛异常。自测 ..、绝对路径、软链三种攻击都被拒。

落笔顺序

  1. 1
    复刻：pathlib 写一份带 frontmatter 的文件。
  2. 2
    改造成 EvidenceStore + EV 编号。
  3. 3
    发一次调用：写两条证据，看编号是否 EV-M-001/002 递增。
  4. 4
    自研防穿越：构造 ../../etc/x 写入，验证被拒。
  5. 5
    验证 frontmatter 字段齐全。

关键提示（≤3）

  • 编号按 kind 分别递增（M/L/T/S），别混。
  • 防穿越用 Path.resolve() 后比较前缀，别用字符串拼接判断。
  • 这个类是 M9/M10 的共同依赖，格式即契约，先定死。

卡住降级路径（30 分钟没思路）

  • 编号乱：确认 new_id 是扫描已有文件自增，不是内存计数（重启会乱）。
  • 视频：证据台账无对口视频，以自研为主。
  • 问 AI：「Python 里我要保证写文件路径必须落在某个基目录内、防 .. 穿越和软链逃逸，正确的校验写法是什么？给校验函数 + 3 个攻击用例。」

任务 T7.2 · 单 Agent 排查 simple_investigator

id：T7.2 ｜ 所属模块：M7 ｜ 优先级：P0

一句话目标：用 create_agent 建一个持全部只读工具的排查 Agent，取证并登记证据、输出带引用的报告。

前置知识（≤2 新概念）

  • create_agent + ReAct 循环：给 Agent 一组工具，它自己决定调哪个、看结果、再调，直到能结论。Java 类比：一个会自己决定调哪个下游接口的循环控制器，你只给它工具和目标。📖 https://docs.langchain.com/oss/python/langchain/agents （create_agent，需核实锚点）· video-2 P10-16「创建 Agent·定义工具」
  • 证据登记做成工具（而非解析自由文本）：给 Agent 一个 record_evidence 工具，让它主动登记，可靠性高于事后解析。Java 类比：让调用方显式调审计接口，而不是从日志里正则抠。📖（复用 T7.1 EvidenceStore）

🟢 第 1 段 · 复刻

  • 读什么：LangChain create_agent(model, tools, response_format=...) 官方最小样例。
  • 跑什么：照样例建一个持 1 个工具的 Agent 跑一次，看它怎么调工具、怎么结束。

🟡 第 2 段 · 改造

  • 写 simple_investigator.investigate(state, tools, model, evidence_store)：create_agent(model, tools, response_format=RcaReport)；system prompt 要点——先看告警+拓扑、每次取证后调 record_evidence 登记、结论必引 [EV-*]。

🔴 第 3 段 · 自研

  • 从空文件写回流逻辑：verifier_feedback 非空时，prompt 附驳回意见并声明"增量补证、复用已有 evidence_id"；token 用量累加进 budget.tokens_used（从 usage metadata 读）。

落笔顺序

  1. 1
    复刻官方 create_agent 样例跑通。
  2. 2
    改造成持全部工具 + record_evidence + RcaReport 输出。
  3. 3
    发一次请求：注入一个真实故障→webhook→看 Agent 是否真调工具取证。
  4. 4
    自研回流：模拟 verifier_feedback，验证增量补证不重头再来。
  5. 5
    验证 report_draft 结论都带 [EV-*]。

关键提示（≤3）

  • 用官方 create_agent，别手写 Agent 循环，也别用已弃用的 create_react_agent。
  • record_evidence 是工具不是解析——让 Agent 主动登记。
  • 这是消融 A2 的正式配置，M10 上线多 Agent 后靠 subagents_enabled 切换，别删。

卡住降级路径（30 分钟没思路）

  • Agent 不调工具：检查工具的 args_schema description 是否让 LLM 看得懂（M3 定义的）。
  • 视频：video-1 P51-55「Agent 概述·调用·绑定工具」逐步兜底；video-2 P14「工具测试和 Agent 整合」。
  • 问 AI：「LangChain create_agent 给了工具但模型总不调 record_evidence 登记证据，我的 system prompt 和工具 description 这样（贴出），怎么让它每次取证后必登记？」

真实 HTTP 验收（含异常路径）

bash
# 注入某故障 → webhook → 看 investigate 产出
curl -XPOST localhost:8000/webhook/alertmanager -d @some-fault-alert.json
ls runs/incidents/inc-*/evidence/*/       # 生成若干 EV 证据
cat runs/incidents/inc-*/report_draft.md  # 结论带 [EV-*] 引用
# 异常路径：网关 degraded 时，证据仍带 degraded 标注落盘，Agent 不假装数据齐全

判定特征：真实注入 → 生成证据 + report_draft（结论带引用）；degraded 被如实标注。依赖真实服务：M2 网关、Prometheus/Loki、DashScope（investigate 模型）。
