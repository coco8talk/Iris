任务 T8.1 · report 节点 + 模板兜底 + 出口

id：T8.1 ｜ 所属模块：M8 ｜ 优先级：P0

一句话目标：从 0 写报告节点：LLM 润色 + 模板兜底 + 结构化字段保护 + HTTP 出口。

前置知识（≤2 新概念）

  • 确定性模板兜底：LLM 调用失败/超时时，用纯 f-string 模板把 RcaReport 渲染成合格 Markdown。Java 类比：像 try{ 调用润色 }catch{ 走本地模板 }，模板是 f-string 不引模板引擎。📖（自研；KISS）
  • 判分字段透传不改：root_service/root_cause/root_detail/confidence/causal_chain 是后续确定性判分的依据，LLM 只准润色 summary_md，不许碰这些字段。Java 类比：DTO 里有一组"只读关键字段"，展示层只能加描述不能改值。📖（复用 M4 的 RcaReport）

🟢 第 1 段 · 复刻

  • 读什么：Python f-string / str.format 渲染 Markdown 的最小写法。
  • 跑什么：手写 report_template.render(report, verdict, budget) -> str，喂一个假 RcaReport，打印出结构完整的 Markdown（结论/置信度/因果链/证据引用清单/修复建议/异议）。

🟡 第 2 段 · 改造

  • 写 report.py：输入 draft_report + verify_verdict + budget；get_model("report") 轻模型只润色 summary_md；验收耗尽仍 fail → confidence="low" + summary 附异议；budget_exhausted → summary 注明"预算耗尽，基于现有证据出具"；落盘 runs/incidents/{id}/report.md。

🔴 第 3 段 · 自研

  • 从空文件写字段透传保护：LLM 返回后，用原 RcaReport 的判分字段覆盖回（防 LLM 偷改）；LLM 调用异常 → 直接走 report_template.render（兜底）。

落笔顺序

  1. 1
    复刻：写模板 render，假数据渲染出完整 Markdown。
  2. 2
    改造：接 LLM 润色 summary_md。
  3. 3
    发一次请求：断网 LLM（改错 key）→ 看是否走模板兜底仍出报告。
  4. 4
    自研字段保护：让 LLM 试图改 root_service → 验证被覆盖回原值。
  5. 5
    加 GET /incidents/{id} 返回报告。

关键提示（≤3）

  • 判分字段必须"LLM 之后覆盖回原值"，别信任 LLM 不改。
  • 三种标注（验收缺席/低置信/预算耗尽）要在 summary 里可见。
  • 模板兜底是 f-string，别引 Jinja（YAGNI）。

卡住降级路径（30 分钟没思路）

  • 兜底没触发：确认 LLM 调用包了 try/except，异常分支真的走 render。
  • 视频：video-2 P82-84「提示词模板·聊天和消息占位符」讲提示词组织（润色 prompt 参考）。
  • 问 AI：「我想让 LLM 只润色报告的 summary_md，但保证 root_service 等字段它改了也无效，正确的做法是什么（提示约束 + 代码覆盖双保险）？」

真实 HTTP 验收（含异常路径）

bash
# 跑一次完整事故到 report
curl -XPOST localhost:8000/webhook/alertmanager -d @some-fault-alert.json
cat runs/incidents/inc-*/report.md   # 含全部 section + [EV-*] 引用
curl -s localhost:8000/incidents/inc-xxx   # 返回结构化字段 + summary_md
# 异常路径：把 report 模型 key 改错 → 仍走模板兜底产出 report.md（LLM 失败不等于无报告）

判定特征：报告含全部 section 与 [EV-*]；断 LLM 走兜底仍出报告；判分字段未被 LLM 篡改。依赖真实服务：DashScope（report 轻模型）。
