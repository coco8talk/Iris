本模块的能力边界（先对齐）

  • RcaReport 由 M7 定义，本模块只渲染不重定义——真要改字段，改 state.py 里 M7 那份，别在这里另立一个报告模型。
  • verify_verdict 此时还是 M4 写的确定性预检结果（只有 pass/fail），M9 才会给它补上跨家族 LLM 的 objections。所以本模块的"验收缺席/低置信"标注要写成能兼容两种情况的形状。
  • 工具集不变：M7 已把 7 个工具全部接入，report 节点本身不调工具。

任务 T8.1 · report 节点 + 模板兜底 + HTTP 出口

id：T8.1 ｜ 所属模块：M8 ｜ 优先级：P0

一句话目标：把 report 占位节点填成"LLM 润色 + 模板兜底 + 判分字段保护 + 落盘 + HTTP 出口"的完整出口。

前置知识（≤2 新概念）

  • 确定性模板兜底
    1. LLM 调用失败/超时/解析异常时，用纯 f-string 模板把 RcaReport 渲染成一份合格 Markdown。
    2. 兜底不是"降级到一份烂报告"——结构化字段本来就是 M7 查出来的，模板渲染出的报告在判分维度上和润色版完全等价，差的只是文字流畅度。
    3. 用 f-string 不引 Jinja（YAGNI，模板只有一份且不需要用户自定义）。
    4. Java 类比：try{ 调用润色服务 }catch{ 走本地模板 }，本地模板是编译期就在的兜底路径。
  • 判分字段透传不改
    1. root_service/root_cause/root_detail/confidence/causal_chain/evidence_ids 是 M12 确定性判分的依据。
    2. LLM 只准润色 summary_md，其余字段一律在 LLM 返回后用原值覆盖回去——不能只在 prompt 里请求它别改。
    3. 双保险：prompt 里说清楚（省 token、减少无谓重试）+ 代码强制覆盖（真正的保证）。
    4. Java 类比：DTO 里有一组只读关键字段，展示层只能加描述不能改值，且序列化前会被重新赋回。

🟡 第 1 段 · 改造 A（先用真实数据把模板写出来）

不要造假 RcaReport 来试模板——M7 已经真实跑出过 report_draft.md 和 state 里的结构化结论，直接拿它当输入：

  1. 跑一次 M7 的完整流程，从 runs/incidents/{id}/report_draft.md 拿到一份真实的 RcaReport；
  2. 写 report_template.render(report: RcaReport, verdict, budget) -> str，section 固定为 6 段：
    1. 结论：root_service + root_cause + root_detail；
    2. 置信度：confidence，以及三种标注（见下）中命中的那几条；
    3. 因果链：causal_chain 逐条编号列出；
    4. 证据引用清单：evidence_ids 每条带上它的文件路径，便于人工翻查；
    5. 修复建议：remediation（为空时写"无自动修复建议，需人工判断"）；
    6. 验收异议：verdict.objections（M4 阶段可能为空列表，M9 之后才有内容）。
  3. 三种标注必须在置信度那一节可见：
    • verdict.verdict == "fail" 且回流轮数已耗尽 → "验收未通过，结论仅供参考"，并把 confidence 强制降为 low；
    • verifier_absent（M9 的 LLM 段解析失败时会置）→ "验收缺席，未经跨家族核验"；
    • budget.budget_exhausted → "预算耗尽，基于现有证据出具，可能存在未排查的方向"。

🟡 第 2 段 · 改造 B（接 LLM 润色 + 落盘 + 出口）

  1. nodes/report.py：读 draft_report_ref 指向的草稿 + verify_verdict + budget；
  2. get_model(AgentRole.REPORT)（轻模型）只润色 summary_md，prompt 里明确"只改这一个字段的文字表达，不得改变任何事实与结论"；
  3. 落盘 runs/incidents/{id}/report.md（目录仍走 M5 的 incident_dir()），state 里更新引用字段；
  4. mark_status(incident_id, "closed")（M5 的 store），事故到此收口；
  5. app.py 新增出口：

🔴 第 3 段 · 自研（字段透传保护 + 兜底触发）

从空文件写保护逻辑：

  1. LLM 返回后，用原始 RcaReport 的判分字段整体覆盖回去，只保留它给的 summary_md：
    python
    polished = original.model_copy(update={"summary_md": llm_summary})
    这样即使模型把 root_service 改成了别的，也一个字都进不了最终报告；
  2. LLM 调用抛任何异常（网络、超时、解析）→ 直接走 report_template.render(original, verdict, budget)，并在报告里标一行"摘要由模板生成"；
  3. 兜底路径必须也落盘、也更新 state、也 mark_status("closed")——最容易漏的就是异常分支里少做了这几件事，结果报告有了但事故状态永远停在 running。

落笔顺序

  1. 1
    跑一次 M7 完整流程，拿到一份真实的 report_draft.md。
  2. 2
    写 report_template.render，用这份真实数据渲染，肉眼核对 6 个 section 齐全、[EV-*] 引用都在。
  3. 3
    在 nodes/report.py 里先只调模板（不接 LLM），跑一次完整事故，确认 report.md 落盘、incident.status='closed'。
  4. 4
    接 LLM 润色 summary_md，再跑一次，对比两份报告：除 summary_md 外应逐字相同。
  5. 5
    自研字段保护：把润色 prompt 故意改成"请把 root_service 改成 pm-auth"，验证最终报告里 root_service 仍是原值。
  6. 6
    自研兜底：把 report 模型的 key 改错，验证仍出 report.md 且状态收口。
  7. 7
    加 GET /incidents/{id}，curl 一次核对响应字段齐全。

关键提示（≤3）

  • 判分字段必须"LLM 之后覆盖回原值"，别信任 prompt 约束——model_copy(update={"summary_md": ...}) 是一行的事。
  • 兜底分支里也要落盘 + 收口状态，否则"报告有了但事故永远 running"。
  • 三种标注（验收未过 / 验收缺席 / 预算耗尽）要在报告正文里可见，不能只留在 state 字段里——报告是给人看的，人不会去翻 checkpointer。

卡住降级路径（30 分钟没思路）

  • 兜底没触发：确认 LLM 调用真的包了 try/except Exception，且异常分支里调的是 render 而不是 raise。
  • 报告里 [EV-*] 引用点不开：确认证据清单那一节输出的是 EvidenceStore 给的真实路径，不是自己拼的。
  • GET /incidents/{id} 404：确认查的是 incident 表 + 落盘文件两处，且 incident_id 过了 incident_dir() 的白名单校验（畸形 id 应该 400 而不是 500）。

cd iris-agent-platform

# 期望：结构化字段 + summary_md 全在；root_service 与 report.md 里一致

# 异常路径 ①：把 report 角色的模型 key 改错 → 仍走模板兜底产出 report.md，状态仍收口 closed
# 异常路径 ②：润色 prompt 改成"请把 root_service 改成 pm-auth" → 最终报告 root_service 仍是原值

判定特征：报告含全部 section 与 [EV-*]；断 LLM 走兜底仍出报告且状态收口；判分字段无法被 LLM 篡改；畸形 id 被挡在路径校验之外。依赖真实服务：DashScope（report 轻模型）、M5 的 webhook 入口。
